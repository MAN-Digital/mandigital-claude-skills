# Script Templates

## Long-form tutorial

Modeled on the validated golden-sample scripts (see
[golden-samples.md](golden-samples.md)) — Romeo read these fluently on camera.

1. **Cold open (10–20s)** — a two-line concrete scenario with real numbers, in the ICP's
   world (see the cold-open section of
   [voice-and-positioning.md](voice-and-positioning.md)). Not a feature announcement — the
   title and thumbnail already did that. No audience-directed question. Example: "Two sales
   reps sell the same service. One quotes five thousand euros. The other quotes four
   thousand."
2. **Name the fix + first-person roadmap** — one or two lines. "This is the problem price
   books solve… I will explain price books. Then we will build and test one." No "welcome
   back," no company introduction, no bulleted agenda.
3. **Ground the concept with a simple example** — before any tool screen, walk one concrete
   mini-case (named segment, real prices). Apply the sequencing principle: visibility →
   governed workflow → AI, in that order. Never open with a feature.
4. **Requirements** — plan/tier, beta status and how to request it, permissions. One chunk,
   stated as plain facts (verified per SKILL.md Step 4).
5. **Walkthrough** — screen-by-screen, one concrete action per beat, structured as visible
   chapters (beat separators in the Reader Script). Every abstract term gets an inline
   "For example: …" (SKILL.md Step 6). When narrating demo footage, anchor the reader:
   "In the example shown here…" No vague "then you configure things."
6. **Mistakes / gotchas** — 3–5 specific failure modes as plain do/don't sentences, not
   aphorisms. Enumerated one per line with spoken ordinals.
7. **Show the finished artifact** — the completed price book / workflow / dashboard, so the
   viewer sees the end state. Note it in the Cue Sheet.
8. **Pre-flight checklist** — "Before you finish, check five things. One: … Two: …" — one
   item per line.
9. **Soft CTA** — one line, help-shaped: "If your HubSpot pricing is difficult to control,
   send us the setup. We will show you where it breaks." No hard sell, no
   subscribe-begging.

## Shorts (under 60 seconds)

One point. One example. Hook in the first 3 seconds by stating the consequence, not asking a
question. No chapters, no recap section — point, then proof, then an optional one-line CTA.

## Promotional

Lead with the specific business problem and its concrete consequence for the ICP persona.
One proof point — a real number or real client outcome from the Client Case Studies file,
never invented. One clear next step. No "in today's landscape" framing, no adjective
stacking.

## Case study

Structure loosely on StoryBrand (see
[voice-and-positioning.md](voice-and-positioning.md)): the client is the hero, MAN Digital is
the guide. Problem (the client's actual before-state) → plan (what MAN Digital built) →
result (real numbers only, from the Client Case Studies file). Never fabricate a metric — if
the file has no number for a claim, describe the qualitative change instead of inventing one.

## Brain-dump transform mode

Triggered when the user pastes another video's script or transcript, or hands you an actual
source video file, YouTube URL, or Loom URL, instead of giving a topic. About 90% of these
are tutorial screen-shares in a tool, usually HubSpot.

0. **If you have the actual source video (a file, a YouTube URL, or a Loom URL), not just
   typed transcript text**, and it has enough distinct on-screen frames that guessing the
   sequence from prose is risky, run
   [video-grounded-storyboard.md](video-grounded-storyboard.md) first. It gives you a real,
   timestamped event list instead of an inferred one — use that as your source-of-truth for
   step 1 below rather than reading the video description you were given.
1. **Read the whole transcript first** (or the video-events output from step 0). Identify
   the actual sequence of on-screen actions — what tool, what clicks, what gets shown, in
   what order. This sequence is the footage being narrated over, and it stays intact.
2. **Fact-check the source against current reality** (SKILL.md Step 4). Source videos age:
   a demo recorded under "Commerce Hub" now lives under "Revenue Hub." Verify feature
   names, UI locations, tier requirements, and beta status by research before narrating
   them — never inherit the source's product facts unchecked.
3. **Do not translate line-by-line.** The source video's opinions, jokes, CTAs, and
   interpretation are not MAN Digital's. Only the screen-action sequence carries over.
4. **Re-derive the angle.** For each screen beat, ask what MAN Digital would say about it
   from a RevOps/governance standpoint, using the sequencing principle (visibility →
   workflow → AI). Reframe around the business consequence, not the feature.
5. **Harvest the source's concrete examples.** If the source (often a HubSpot community
   Loom) walks a specific example, name that example in the script ("In the example shown
   here…") and mark the source segment in the Cue Sheet so the editor can screen-share it —
   the target format is roughly 20% presenter / 80% demo footage.
6. **Strip source-video artifacts**: rhetorical hooks ("Pretty cool, right?"), generic
   influencer sign-offs ("smash that like button"), and unverifiable claims about the tool.
   Replace with MAN Digital's own framing and CTA.
7. **Apply the main skill's Steps 1–8** (clarifying questions, voice grounding, fact-check,
   readability, term-level examples, blocklist, structure) exactly as if this were a fresh
   script.
